# AGENTS.md — SFERA-AI

> Универсальные инструкции для любых AI-агентов, работающих в этом репозитории.
> Файл должен оставаться сжатым навигатором, а не сводом знаний: подробности хранятся в
> `project-context/`. Если в подпапке появится свой `AGENTS.md`, для файлов этой подпапки
> действуют более локальные инструкции.

## Что за проект

SFERA-AI — отдельный сервис (отдельный git-репозиторий и деплой) AI-анализа кандидатов
для SFERA. Основной продукт находится в соседнем репозитории `FullSphera`. Сервис читает
данные платформы — кандидатов, ответы, резюме и видео — напрямую из той же PostgreSQL,
что использует `sfera_backend`: **без Django ORM**, через SQLAlchemy reflection. Запись
разрешена только в собственные таблицы `ai_*`; таблицы платформы доступны только для чтения.

**Перед планированием или изменением кода полностью прочитай
[`project-context/sfera-ai/00_START_HERE.md`](project-context/sfera-ai/00_START_HERE.md).**
Далее следуй указанному там порядку: PRD → CONTEXT → TDD → EPICS → STATE → план текущего
шага. Не переноси подробности из этих документов сюда.

Технический контекст платформы SFERA зафиксирован в
[`project-context/PLATFORM_AUDIT_REFERENCE.md`](project-context/PLATFORM_AUDIT_REFERENCE.md).
Это снепшот аудита от 2026-08-21. Если он расходится с реальностью, проверяй актуальный код
`FullSphera/sfera_backend/`, когда этот репозиторий доступен агенту.

План внешнего пайплайна транскрибации видео находится в
[`project-context/PLATFORM_video-transcription-plan/`](project-context/PLATFORM_video-transcription-plan/).
Он описывает внешний источник видео-фактов, а не код, который нужно реализовать в SFERA-AI.
Перед использованием конкретных таблиц и полей сверяйся с актуальной реализацией платформы.

## Как работать агенту

- Не считай сведения из истории чата актуальнее репозитория. Текущий прогресс и следующий
  шаг всегда проверяй в `project-context/sfera-ai/04_STATE.md`.
- Сначала исследуй существующий код и документы, затем предложи план и критически оцени риски.
  К реализации переходи только после явного одобрения владельца: «начинай», «приступай» или
  другого недвусмысленного разрешения.
- Используй доступные конкретному агенту инструменты. Для навигации по коду сначала применяй
  CodeGraph (`codegraph explore "<вопрос>"` или эквивалентный инструмент), если он доступен и
  индекс актуален; иначе используй `rg`/`rg --files` и точечное чтение файлов.
- После структурных изменений синхронизируй индекс командой `codegraph sync`, если CodeGraph
  доступен. Недоступность агент-специфичного инструмента не должна блокировать работу.
- Сохраняй существующий стиль и архитектурные решения. Не делай попутных рефакторингов без
  необходимости и не перезаписывай несвязанные изменения пользователя или другого агента.
- Проверяй изменения минимально достаточными тестами, а перед завершением — более широким
  релевантным набором. Основная команда проекта: `uv run pytest`.
- После выполненного и проверенного шага обновляй его журнал и
  `project-context/sfera-ai/04_STATE.md`; не объявляй шаг завершённым без проверки критериев DoD.
- Объясняй владельцу решения простым языком: он знает продукт, но не обязан знать детали
  Python, SQLAlchemy, инфраструктуры или внутренних инструментов агента.

## Текущее состояние

Roadmap E0–E12 завершён согласно `04_STATE.md` на 2026-09-01. Следующее действие не выбрано:
владелец должен решить, пересобирать ли полный прогон курса 39 с реальными резюме или выполнять
реальный E10-01 прогон. **Не начинай ни один из этих вариантов без явного решения владельца.**

Эта секция — только краткий указатель. При любом расхождении приоритет имеет
[`project-context/sfera-ai/04_STATE.md`](project-context/sfera-ai/04_STATE.md).

## Обязательные ограничения

- Не изменяй `sfera_backend`, `SPHERA` или другие репозитории без отдельного явного разрешения
  на каждую конкретную правку. Текущее согласованное исключение — работа с общей docker-сетью,
  описанная в разделе «Инфраструктура и сеть» `03_TDD.md`; перед действием всё равно проверь
  точные границы разрешения в плане шага.
- Подключение к БД платформы выполняется только read-only пользователем PostgreSQL. Никогда не
  пиши в таблицы `courses_*`, `testchecks_*`, `users_*`, `headhunter_*` и любые другие таблицы
  платформы.
- Изменения схемы и данные SFERA-AI ограничены собственными таблицами `ai_*`.
- Реальные LLM-вызовы, прод-прогоны, выдача `GRANT`, изменения контейнеров/сетей и любые действия
  с внешними системами выполняй только в пределах явно согласованного шага и разрешения владельца.
- Соблюдай принцип «один факт — один файл»: не дублируй подробный прогресс вне `04_STATE.md`,
  а архитектурные решения — вне предназначенных для них документов контекста.
- Не коммить секреты и не выводи содержимое `.env`, токены, пароли или персональные данные в
  логи, тестовые артефакты и ответы пользователю.
