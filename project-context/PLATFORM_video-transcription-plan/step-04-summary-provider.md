# Step 04 — SummaryProvider (LLM): краткое summary содержания речи

**Статус:** ⬜ TODO
**Зависит от:** выбор LLM-провайдера — **решено (2026-09-07): GPT-4o-mini через прокси** (proxyapi/vsegpt, РФ-прокси, оплата в рублях).
**Цель:** из транскрипта сделать короткое summary для HR — о чём говорил кандидат, какой там текст.
**Упрощено владельцем (2026-09-07):** без классификации/вердикта (TARGET/NON_TARGET) — только
транскрибация + понимание содержания. Просто текст + краткий пересказ.

## Интерфейс

```python
class SummaryResult(NamedTuple):
    summary: str            # 3–6 предложений: о чём говорит кандидат

class SummaryProvider(Protocol):
    def summarize(self, transcript: str, is_empty: bool, context: dict) -> SummaryResult: ...
```

`context` — минимум метаданных (название вакансии/должности), для более уместного пересказа.

## Настраиваемый промпт и критерии (требование владельца)

> Промпт составлю позже — он должен быть гибко настраиваемым: задавать критерии, по которым оцениваем текст.

Промпт **не хардкодим**. Храним шаблон в настройке, редактируемой без релиза:
- **Модель `SummaryPromptTemplate`** (или запись в существующих settings/конфиге): поля
  `system_prompt`, `criteria` (опционально — на будущее, если понадобится оценка сверх пересказа),
  `is_active`. Редактируется в Django-admin.
- Возможна привязка **к компании/вакансии** — заложить FK на будущее, в волне 1 достаточно одного
  глобального активного шаблона.
- Промпт собирается из шаблона + подстановок (`{position}`, `{criteria}`, `{transcript}`).
- Владелец пришлёт текст промпта/критериев позже → просто заполняем активный шаблон, код не трогаем.

## Логика

1. **Если `is_empty` (речь не распознана / тишина / кандидат молчал):**
   - LLM **не вызываем** (экономия). Сразу:
     `summary = "Кандидат не произнёс распознаваемой речи (тишина/пустая запись)."`
2. **Иначе** — вызвать LLM с промптом:
   - Роль: помощник HR. Дать краткий пересказ того, что кандидат рассказал о себе.
   - Просить **строгий JSON** `{summary}` для надёжного парсинга.
   - Температура низкая, лимит токенов небольшой (транскрипт 3-мин ≈ 400–600 слов).

## Реализация (по env `SUMMARY_PROVIDER`)

- **ProxyLLMProvider** — `gpt-4o-mini` через proxyapi/vsegpt — единственный провайдер по умолчанию
  (решение владельца 2026-09-07). Абстракция (`Protocol`) остаётся — на будущее можно добавить
  альтернативу (GigaChat и т.п.) без правок воркера, но реализовывать сейчас не нужно.

## Промпт-каркас (дефолтный шаблон, владелец заменит своим)

Дефолт в БД-шаблоне, редактируется без релиза:
```
{system_prompt}                     # напр. «Ты — ассистент HR…»
Должность: {position}
Сделай краткий пересказ (3–6 предложений): о чём кандидат рассказал о себе, что важного сказал.
Ответ строго JSON: {"summary": "..."}.
Расшифровка: """{transcript}"""
```

## Крайние случаи

- LLM вернул невалидный JSON → retry с более строгой инструкцией; после N попыток — сохранить сырой
  ответ в `summary`, не падать.
- Провайдер недоступен (сеть/лимит) → job → retry (step-05), не терять.

## Стоимость

Транскрипт 3-мин ≈ 400–600 слов ≈ ~800 токенов in + ~250 out, `gpt-4o-mini` через прокси.

## Критерий готовности

- [ ] Непустой транскрипт → осмысленное summary содержания.
- [ ] Пустой транскрипт → сообщение о тишине без вызова LLM.
- [ ] Невалидный ответ LLM не роняет воркер.
