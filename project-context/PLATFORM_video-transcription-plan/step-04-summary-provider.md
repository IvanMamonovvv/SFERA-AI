# Step 04 — SummaryProvider (LLM): summary + вердикт + обработка пустого видео

**Статус:** ⬜ TODO
**Зависит от:** выбор LLM-провайдера.
**Цель:** из транскрипта сделать короткое summary для HR + вердикт. Пустой транскрипт → явный вывод «нецелевой / данных нет».

## Интерфейс

```python
class SummaryResult(NamedTuple):
    summary: str            # 3–6 предложений для HR
    verdict: str            # TARGET | NON_TARGET | NO_DATA (enum)

class SummaryProvider(Protocol):
    def summarize(self, transcript: str, is_empty: bool, context: dict) -> SummaryResult: ...
```

`context` — минимум метаданных (название вакансии/должности), чтобы вердикт был осмысленным.

## Настраиваемый промпт и критерии (требование владельца)

> Промпт составлю позже — он должен быть гибко настраиваемым: задавать критерии, по которым оцениваем текст.

Промпт **не хардкодим**. Храним шаблон и критерии оценки в настройке, редактируемой без релиза:
- **Модель `SummaryPromptTemplate`** (или запись в существующих settings/конфиге): поля
  `system_prompt`, `criteria` (текст/список критериев), `verdict_labels`, `is_active`. Редактируется в Django-admin.
- Возможна привязка **к компании/вакансии** (разные критерии под разные роли) — заложить FK на будущее,
  в волне 1 достаточно одного глобального активного шаблона.
- Промпт собирается из шаблона + подстановок (`{position}`, `{criteria}`, `{transcript}`).
- Владелец пришлёт текст промпта/критериев позже → просто заполняем активный шаблон, код не трогаем.

## Логика

1. **Если `is_empty` (речь не распознана / тишина / кандидат молчал):**
   - LLM **не вызываем** (экономия). Сразу:
     `verdict = NO_DATA`, `summary = "Кандидат не произнёс распознаваемой речи (тишина/пустая запись).
     Оценить по видеовизитке невозможно — вероятно нецелевой, требуется ручная проверка."`
2. **Иначе** — вызвать LLM с промптом:
   - Роль: помощник HR. Дать: краткое резюме что кандидат рассказал о себе, релевантность должности,
     красные флаги; в конце — вердикт одним словом из набора.
   - Просить **строгий JSON** `{summary, verdict}` для надёжного парсинга.
   - Температура низкая, лимит токенов небольшой (транскрипт 3-мин ≈ 400–600 слов).

## Реализации (по env `SUMMARY_PROVIDER`)

- **GigaChatProvider** (нативный РФ, есть free-tier) — по умолчанию, если есть ключ.
- **ProxyLLMProvider** — GPT-4o-mini / Claude Haiku через proxyapi/vsegpt (РФ-прокси, оплата в рублях).

## Промпт-каркас (дефолтный шаблон, владелец заменит своим)

Дефолт в БД-шаблоне, редактируется без релиза:
```
{system_prompt}                     # напр. «Ты — ассистент HR…»
Должность: {position}
Критерии оценки: {criteria}         # ← задаёт владелец, гибко
Сделай краткое summary (3–6 предложений) по критериям + красные флаги.
Затем вердикт: TARGET / NON_TARGET / NO_DATA.
Ответ строго JSON: {"summary": "...", "verdict": "TARGET|NON_TARGET|NO_DATA"}.
Расшифровка: """{transcript}"""
```

## Крайние случаи

- LLM вернул невалидный JSON → retry с более строгой инструкцией; после N попыток — сохранить сырой ответ
  в `summary`, `verdict = NO_DATA`, не падать.
- Очень короткая речь («Здравствуйте» и всё) → не is_empty, но LLM сам поставит NO_DATA/NON_TARGET.
- Провайдер недоступен (сеть/лимит) → job → retry (step-05), не терять.

## Стоимость

Транскрипт 3-мин ≈ 400–600 слов ≈ ~800 токенов in + ~250 out → ~0.05–0.1₽/кандидат (или бесплатно на free-tier GigaChat).

## Критерий готовности

- [ ] Непустой транскрипт → осмысленное summary + валидный verdict.
- [ ] Пустой транскрипт → NO_DATA без вызова LLM.
- [ ] Невалидный ответ LLM не роняет воркер.
- [ ] Переключение `SUMMARY_PROVIDER` работает без правок воркера.
