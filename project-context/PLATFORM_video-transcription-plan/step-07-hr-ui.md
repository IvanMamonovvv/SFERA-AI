# Step 07 — UI в карточке кандидата (HR/Admin)

**Статус:** ⬜ TODO
**Зависит от:** step-06.
**Цель:** HR видит рядом с видеовизиткой: статус обработки, итоговое summary + вердикт, и может раскрыть полный транскрипт.

## Где (FSD)

- `SPHERA/src/domains/Candidate/model/candidate-model.ts` — расширить `CandidateAnswerItem`:
  ```ts
  transcription?: {
    status: 'PENDING' | 'PROCESSING' | 'DONE' | 'FAILED';
    summary: string;
    verdict: 'TARGET' | 'NON_TARGET' | 'NO_DATA' | '';
    transcript: string;
    isEmpty: boolean;
  };
  ```
- `lib/candidate-answers-mapper.ts` — смаппить новое поле из API.
- Компонент отображения видеоответа (в `domains/Candidate/` / соответствующем виджете) — добавить блок.

## UX

- Рядом с плеером видеовизитки — блок «Разбор видеовизитки»:
  - **Бейдж статуса:** `В обработке…` (PENDING/PROCESSING, спиннер) / `Готово` / `Ошибка`.
  - **Вердикт** цветным чипом: TARGET (зелёный) / NON_TARGET (серый) / NO_DATA (жёлтый).
  - **Summary** — 3–6 предложений, всегда на виду.
  - **Транскрипт** — под спойлером «Показать расшифровку» (может быть длинным).
- Кейс пустого видео (`isEmpty`/NO_DATA): показать понятный текст «Кандидат ничего не сказал —
  оценить нельзя, вероятно нецелевой», а не пустоту.
- PENDING/PROCESSING: можно мягкий поллинг статуса или обновление при перезаходе (не делать агрессивный
  поллинг — результат не срочный).

## Критерий готовности

- [ ] У обработанной визитки видно summary + вердикт, транскрипт раскрывается.
- [ ] Необработанная — статус «в обработке», без ошибок вёрстки.
- [ ] Пустое видео → понятная формулировка, не пустой блок.
- [ ] Кандидат этих данных не видит (RBAC на уровне API, UI — только HR/Admin роут).
