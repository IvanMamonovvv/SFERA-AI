# EXECUTION_PLAN — порядок реализации шагов 02–10

> Не дублирует содержимое step-файлов (один факт — один файл, см. `CLAUDE.md`). Здесь —
> только порядок выполнения, кто что делает, и что я конкретно буду менять на каждом шаге.
> Детали/DoD/крайние случаи каждого шага — в соответствующем `step-NN-*.md`.

## Важное ограничение (правило проекта)

Все шаги 02–10 — код `sfera_backend`/`SPHERA` (другой репозиторий, не `SFERA-AI`). По
`CLAUDE.md`: **менять этот код нельзя без отдельного явного разрешения владельца на
каждую конкретную правку.** Этот файл фиксирует НАМЕРЕНИЕ и порядок — не разрешение.
Перед стартом каждого шага буду явно спрашивать «начинай» отдельно, даже если этот
файл уже согласован целиком.

## Решено (2026-09-07)

- **LLM для summary:** GPT-4o-mini через прокси (proxyapi/vsegpt), `SUMMARY_PROVIDER=proxy`.
- **Скоуп step-04 упрощён:** только транскрибация + краткое понимание содержания (о чём
  говорит кандидат, какой там текст) — без классификации/вердикта (TARGET/NON_TARGET/
  NO_DATA убраны из плана, см. `step-04-summary-provider.md`).

**Остаётся открытым:** точный текст системного промпта/критериев — хранится в БД-шаблоне
`SummaryPromptTemplate`, редактируется без релиза, владелец может прислать/поменять
в любой момент без правок кода.

## Порядок и что буду делать на каждом шаге

1. **step-02 — постановка в очередь.** Хук в `testchecks/views.py::perform_create` (или
   `post_save`-сигнал — выбрать при реализации), `transaction.on_commit`,
   `TranscriptionJob.objects.get_or_create(answer=answer)`, обработка перезаписи видео,
   `TRANSCRIBE_ENABLED` feature-flag (default off). Только `VIDEO_RECORDING`, не
   `LessonMedia`.
2. **step-03 — TranscriptionProvider.** `testchecks/services/transcription/base.py`
   (Protocol) + `LocalFasterWhisperProvider` (модель-синглтон на процесс, `language=ru`),
   ffmpeg-извлечение аудио во временный wav, `TRANSCRIBE_PROVIDER` env-рубильник (local
   по умолчанию; yandex/proxy — заглушки интерфейса, не обязательно реализовывать сразу
   в полном объёме, если владелец не просит).
3. **step-04 — SummaryProvider.** `ProxyLLMProvider` (`gpt-4o-mini` через proxyapi/vsegpt),
   `SummaryPromptTemplate` модель/конфиг (редактируется без релиза), пустой транскрипт →
   сообщение о тишине без вызова LLM (экономия), строгий JSON-парсинг с retry. Без
   классификации/вердикта — только `summary` (пересказ содержания).
4. **step-05 — воркер.** `run_transcription_worker` management-команда, `SELECT ... FOR
   UPDATE SKIP LOCKED` для безопасного pull, reaper зависших `PROCESSING`, retry/`MAX
   attempts`→`FAILED`.
5. **step-06 — API.** Добавить `transcription`-объект в сериализатор карточки кандидата,
   RBAC (только HR/Admin), обновить OpenAPI/`03_API.md`.
6. **step-07 — HR UI.** Правки в `SPHERA` (фронтенд-репозиторий): тип
   `CandidateAnswerItem.transcription`, маппер, блок «Разбор видеовизитки» с бейджем
   статуса/вердиктом/summary/спойлером транскрипта.
7. **step-08 — retention guard.** Проверка в `clean_expired_videos()`/
   `check_disk_pressure()` — не удалять видео с незавершённым джобом (вариант A из
   step-файла: отсрочка с ограничением числа попыток).
8. **step-09 — тесты/smoke.** Юнит на очередь/воркер/edge-cases (особенно пустое видео),
   ручной smoke-чеклист в `06_TEST_CHECKLIST.md`.
9. **step-10 — prod rollout.** `faster-whisper`+модель в образ, новые env, отдельный
   сервис-воркер в `docker-compose`, staging→прод, опциональный backfill старых
   видеовизиток, план отката (остановка контейнера + `TRANSCRIBE_ENABLED=false`).

## Зависимости между шагами (важно для порядка)

- 02 и 03 независимы друг от друга — можно в любом порядке или параллельно.
- 04 зависит только от решённого провайдера LLM, не от 02/03.
- 05 зависит от 01+03+04 (нужен провайдер транскрипции и summary, чтобы воркеру было что
  вызывать).
- 06 зависит только от 01 (модель уже в проде) — можно сделать до 05, но тогда API будет
  всегда отдавать `PENDING`/`null` до готовности воркера. Смысла делать раньше 05 нет.
- 07 зависит от 06.
- 08 зависит от 05 (нечего защищать, пока воркер не пишет DONE).
- 09 — параллельно с реализацией каждого шага (не откладывать тесты в один шаг в конце).
- 10 — последний, после 01–09.
