# Step 00 — Спайк: бенчмарк сервера и выбор параметров

**Статус:** ✅ DONE
**Зачем:** проверить, потянет ли сервер self-hosted whisper, за сколько реально обрабатывается 3-мин видео
и что будет при 5 одновременных. По результатам финализируем модель whisper и `TRANSCRIBE_CONCURRENCY`.
**Код фичи здесь не пишем — только замеры.**

## Факт: VPS = Cloud MSK 80 — `4 × 3.3 ГГц CPU · 8 ГБ RAM · 80 ГБ NVMe · Ubuntu 24.04`

**Мониторинг за месяц уже снял риск нагрузки:** CPU обычно < 20% (простаивает), реально занятой RAM ~2 ГБ
(свободно ~6 ГБ, остальное — кэш), диск 27/80 ГБ. Поэтому спайк теперь — **не проверка «выдержит ли»**
(выдержит с запасом), а: (1) подтверждение реального времени обработки 3-мин видео, (2) проверка **качества
`small` на русском** (иначе `medium` — RAM позволяет), (3) финализация concurrency (2, можно 3).

## Что выяснить (вопросы спайка)

1. Сколько на VPS ядер и свободной RAM в реальной работе (при живом веб + БД)?
2. За сколько `faster-whisper` перемалывает 3-мин русское видео на этом CPU (модели `small` и `medium`)?
3. Пиковая RAM на одну обработку?
4. Что происходит с откликом веб-платформы, когда параллельно идёт 1 / 2 / N транскрибаций?
5. При каком `concurrency` сервер остаётся отзывчивым для пользователей?

## Действия

### 1. Снять характеристики сервера
На VPS:
```bash
nproc                      # число ядер
free -h                    # RAM: total / used / available
cat /proc/loadavg          # текущая нагрузка
df -h /                    # свободное место под модель
docker stats --no-stream   # сколько ест web/db/scheduler сейчас
```
Записать в журнал ниже. Ориентир: на веб-воркеры (gunicorn) уже уходит часть ядер — считаем **свободные**.

### 2. Прогнать faster-whisper на реальном 3-мин видео
Во временном venv/контейнере (не в проде):
```bash
pip install faster-whisper
```
```python
# bench.py — прогон на sample-видео кандидата (взять реальный VIDEO_RECORDING answer)
import time
from faster_whisper import WhisperModel

for size in ["small", "medium"]:
    m = WhisperModel(size, device="cpu", compute_type="int8")
    t = time.time()
    segments, info = m.transcribe("sample_3min.wav", language="ru")
    text = " ".join(s.text for s in segments)
    print(size, "→", round(time.time() - t, 1), "сек,", len(text), "символов")
```
Замерить **время** и через `docker stats`/`top` — **пиковую RAM и загрузку ядер**.
Сравнить качество текста `small` vs `medium` на русском на глаз.

### 3. Симуляция пиков
Запустить **5 транскрибаций параллельно** (5 процессов bench.py) → замерить:
- суммарное время до завершения всех 5,
- отзывчивость платформы в этот момент (открыть страницы, замерить latency),
- не уходит ли RAM в своп (`free -h`, `vmstat`).
Повторить для `concurrency = свободные_ядра` и `свободные_ядра - 1`.

## Примечание по пропускной способности (ориентир, уточнить фактом)

Если 3-мин видео на `small` int8 обрабатывается ~60–120 с на ядро, то при `concurrency=2`:
`2 × 3600 / 90 ≈ 80 видео/час`. 200 в завале → ~2.5 ч фоном. Кандидаты «капают», а не приходят
200 в одну секунду, поэтому очередь редко бывает длинной. При недостатке — поднять concurrency
(если есть ядра) или временно включить cloud-рубильник (step-03).
