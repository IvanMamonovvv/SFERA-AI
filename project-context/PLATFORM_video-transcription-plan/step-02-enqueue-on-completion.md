# Step 02 — Постановка задачи в очередь при загрузке видеовизитки

**Статус:** ✅ DONE (2026-09-07)
**Зависит от:** step-01.
**Цель:** как только кандидат **загрузил видеовизитку** (сохранён `Answer` с `VIDEO_RECORDING` + файл в S3) →
сразу создать `TranscriptionJob(PENDING)`. Не ждём завершения всей анкеты.

## Триггер (уточнено владельцем)

> Как только видеовизитка загрузилась какая-то новая — она транскрибировалась и выдавался summary.

То есть точка запуска — **сохранение видеоответа**, а не авто-завершение попытки. Приём ответа —
`testchecks/views.py` → `perform_create` (~строки 280–320), где `Answer` сохраняется с `file`.

## ⚠️ Только видеовизитки кандидата, не видео уроков

Триггер вешаем **строго на `Answer` c `VIDEO_RECORDING`**. Видео, которые грузят HR/админ в урок —
это другая модель `LessonMedia` (путь `course_media/…`, фича `admin-lesson-video`, до 15 мин). Их
**НЕ транскрибируем**. `LessonMedia` идёт по своему пути загрузки и через этот триггер не проходит —
не подключать транскрибацию к `lessons/services/video_processing.py`.

## Действия

1. При сохранении `Answer` с `question.question_type == VIDEO_RECORDING` и непустым `file`:
   `TranscriptionJob.objects.get_or_create(answer=answer)` (идемпотентно).
2. Обернуть в `transaction.on_commit(...)` — задача ставится только после успешного коммита и заливки файла в S3.
3. **Только постановка в очередь** — никакой обработки в веб-запросе. Вставка мгновенная, веб не блокируется
   даже при 5+ одновременных загрузках.

## Перезапись видео (важный кейс)

Модель `Answer` уникальна по (attempt, question) → повторная запись визитки **обновляет тот же `Answer`**,
файл в S3 меняется. Нужно транскрибировать **финальную** версию:
- при сохранении, если файл изменился (сравнить имя/ключ файла или отследить в `Answer.save`) →
  сбросить существующий джоб в `PENDING` (обнулить transcript/summary/attempts) — пере-обработать.
- Реализация: хранить в джобе ссылку на обработанный файл (ключ) и сверять; либо простой флаг «файл новее результата».

## Где вешать (варианты, выбрать при реализации)

- **Явный вызов в `perform_create`** после сохранения ответа (`_enqueue_video_transcription(answer)`),
  в `transaction.on_commit` — просто и очевидно. Рекомендуется.
- Либо **Django signal** `post_save` на `Answer` с фильтром по типу вопроса — чище, но менее явно.

## Feature-flag

- Постановку прятать за env `TRANSCRIBE_ENABLED` (по умолчанию off до раскатки) — чтобы включать/выключать
  триггер без релиза (см. step-10).

## Крайние случаи

- Ответ не видео / файл пустой → задачу не создаём.
- Повторная отправка / ретрай сети → `get_or_create` не плодит дубли (перезапись — см. выше).
- Файл ещё заливается в S3 на момент коммита → `on_commit` + retry воркера при отсутствии файла (step-05).

## Критерий готовности

- [ ] После загрузки видеовизитки в БД появляется ровно один `TranscriptionJob(PENDING)` на видео.
- [ ] Ответ не-видео / без файла не создаёт задач.
- [ ] Перезапись видео → джоб пере-обрабатывается на финальном файле.
- [ ] Веб-ответ на сохранение видеоответа не замедлился (постановка — не обработка).
- [ ] `TRANSCRIBE_ENABLED=false` → триггер не срабатывает.
