## 1. Проблема

Менеджер/HR сейчас вручную сопоставляет кандидата (ответы анкеты, резюме, видео,
данные HH-лида) с требованиями вакансии — без структурированной оценки соответствия
(`Fit`), без истории, почему скор изменился со временем, без учёта собственного
фидбека по прошлым кандидатам этой же вакансии.

## 2. Пользователи

Менеджеры/HR платформы SFERA, работающие со списком кандидатов по вакансии
(`Course`) — те же роли, что видят `CourseCandidatesViewSet` в `sfera_backend`.

## 3. Цели

- Автоматически собирать структурированный профиль фактов о кандидате
  (`CandidateProfile.facts`) из разнородных источников (анкета, резюме, видео,
  HH-лид) без ручного сведения.
- Считать оценку соответствия вакансии (`Fit`) отдельно от фактов о кандидате,
  с evidence и объяснимой историей изменений между версиями.
- Учитывать фидбек менеджера по вакансии (`VacancyMemory`) в последующих оценках.
- Не тратить AI-бюджет на пересчёт того, что не изменилось (change detection).

## 4. НЕ-цели (out of scope)

- Не отдельная сущность `Candidate` вне `ai_analysis` — не дублировать `CustomUser`.
- Не собственная транскрибация видео — читает готовый результат внешнего плана
  (`PLATFORM_video-transcription-plan/`), не реализует пайплайн заново.
- Не UI на этом этапе — только read API (раздел «API/контракты» `03_TDD.md`).
- Не daily/monthly hard-cap на AI-расходы на MVP (см. открытый вопрос №4 ниже).
