# Шаг E13-01 — Приоритет резюме в промпте fit-scoring

**Статус:** TODO
**Слой:** Backend (fit-scoring) · **Зависит от:** E6-01 (`candidate_facts.py`,
факты уже несут `evidence[0].source_type`), E6-03 (`fit_scoring.py`)
**Перед началом:** прочитай `src/sfera_ai/services/fit_scoring.py` (`_SYSTEM_PROMPT`,
`_build_messages`), `src/sfera_ai/services/candidate_facts.py` (как факты помечаются
источником — `evidence`), [[project_source_priority_resume_answers_video]] (решение
владельца 2026-09-01).

## Контекст

Владелец 2026-09-01 сформулировал: резюме — важнейший источник данных о кандидате
(связь с кандидатом + опыт), 2-й по значимости — ответы на анкету, 3-й — видеовизитка.
При противоречии между источниками по одному и тому же параметру (например разный
опыт работы в резюме и в ответе) — верить резюме, остальные источники не отбрасывать,
использовать как дополнение там, где в резюме этого параметра нет. Явно уточнено:
это НЕ hard-block и НЕ блокировка кандидата — при малом объёме данных оценка должна
органически быть ниже/осторожнее, не через искусственный потолок.

Сейчас `_build_messages` (`fit_scoring.py`) передаёт LLM плоский список
`candidate_profile.facts` без указания на приоритет между источниками — модель не
знает, что резюме важнее анкеты при конфликте.

## Цель

При противоречии между источниками ИИ в оценке кандидата отдаёт приоритет резюме;
факты из ответов/видео используются как дополнение, не отбрасываются.

## Что сделать

1. Проверить, что каждый факт в `profile.facts` действительно несёт
   `evidence[0].source_type` (`HH_RESUME`/`ANKETA_FILE`/`ANSWER`/`VIDEO`) — уже так
   устроено в `_resume_facts`/`_answers_facts`/`_video_facts` (`candidate_facts.py`).
2. Дополнить `_SYSTEM_PROMPT` в `fit_scoring.py`: явная инструкция — при конфликте
   значений одного и того же параметра между источниками резюме (`HH_RESUME`/
   `ANKETA_FILE`) приоритетнее ответов (`ANSWER`), ответы приоритетнее видео
   (`VIDEO`); при отсутствии значения в приоритетном источнике — брать из следующего
   по приоритету без штрафа.
3. Явно закрепить в промпте: нехватка данных НЕ повод для искусственного занижения
   ниже того, что подтверждают присутствующие источники — оценка отражает реальный
   объём и качество доступных фактов, не блокирует кандидата статусом.
4. Проверить на 6 кандидатах, уже пересчитанных в E11-02 (`fit_score=75` до/после
   резюме) — вердикты не должны неожиданно разъехаться относительно того сравнения
   без причины (сравнить summary/strengths/risks на предмет использования резюме
   вместо анкеты при конфликте).
