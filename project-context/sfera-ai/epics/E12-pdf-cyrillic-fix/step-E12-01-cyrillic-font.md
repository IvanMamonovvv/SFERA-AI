# Шаг E12-01 — Кириллица в PDF AI-карточки

**Статус:** TODO
**Слой:** Backend (export) · **Зависит от:** E9-01/E9-04 (`ai_card.py` уже существует)
**Перед началом:** прочитай `src/sfera_ai/services/export/ai_card.py` (текущие стили,
`_STYLE_*` на `Helvetica`/`Helvetica-Bold`), `step-E9-04-styled-candidate-card.md`.

## Контекст

Найдено 2026-09-01 на реальной AI-карточке (course_id=39, кандидат #2378): весь
кириллический текст в PDF рендерится чёрными прямоугольниками, читаются только цифры и
латиница (`phone_number`, `Fit-score: 75`, `STRONG_MATCH`). Причина — `ai_card.py`
использует встроенные AFM-шрифты ReportLab (`Helvetica`/`Helvetica-Bold`), которые не
поддерживают кириллицу. Существующие тесты (`test_ai_card_export.py`) проверяют
структуру/данные PDF, не визуальный рендер шрифта — баг не был пойман раньше.

## Цель

AI-карточка на реальном кандидате читаема — весь русский текст (имя, summary, strengths,
risks, факты) рендерится нормальными кириллическими глифами, не квадратами.

## Что сделать

1. Найти/подключить TTF-шрифт с кириллицей (например, DejaVuSans — часто уже доступен в
   системных пакетах Linux/Docker-образа, либо добавить как зависимость шрифт-файл в
   репозиторий/пакет).
2. Зарегистрировать шрифт через `reportlab.pdfbase.pdfmetrics.registerFont` +
   `reportlab.pdfbase.ttfonts.TTFont` в `ai_card.py`, завести regular+bold варианты.
3. Заменить все `fontName="Helvetica*"` в `_STYLE_*` (`ai_card.py`) на новый
   зарегистрированный шрифт.
4. Проверить, что Dockerfile/прод-окружение реально имеет доступ к файлу шрифта (не
   только локальная машина разработчика) — если шрифт не в pip-пакете, добавить в
   Dockerfile или зависимость с шрифтом внутри (например, pip-пакет с TTF-файлами).

## Файлы

- `src/sfera_ai/services/export/ai_card.py` — регистрация шрифта, замена `fontName`
- `Dockerfile` — при необходимости, если шрифт не ставится через pip-зависимость
- `pyproject.toml` — если шрифт подключается через pip-пакет (например, есть пакеты с
  зашитыми TTF)
