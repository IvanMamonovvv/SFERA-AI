Контекст — решение владельца 2026-09-10: карточка должна визуально/по содержанию
приближаться к эталону РТХ (`step-E17-06-rtx-visual-style-match.md`) — там `summary`
читается как список буллетов (не абзац), `strengths`/`interview_questions`
конкретны (факты с датами/цифрами, проверяемые вопросы), критерии оценки — единая
шкала 0-10.

## Цель

`CandidateVacancyAnalysis` после `run_fit_scoring` содержит `summary` как список
строк, `strengths`/`interview_questions` — конкретные формулировки (не абстракции),
`criteria_scores` — значения по шкале 0-10 (или `null` для неоценённых критериев).

## Что сделать

1. `_SYSTEM_PROMPT` (строки 25-46) — переформулировать требования к полям:
   - `summary` — список из 3-5 отдельных предложений (JSON-массив строк, не
     сплошной текст) — что подтверждено фактами, что не указано.
   - `strengths` — каждый пункт с конкретным фактом (дата/цифра/название
     компании) из evidence, не общая формулировка.
   - `interview_questions` — конкретные проверяемые вопросы для интервью, не
     общие темы.
   - `contradictions` — готовая формулировка-предупреждение для менеджера
     (напр. "Не считать X доказательством Y без подтверждения Z"), не просто
     список расхождений.
   - `criteria_scores` — шкала 0-10 (число с шагом 0.5, либо `null`, если
     критерий не оценить по доступным данным) — сейчас шкала свободная.
2. `_parse_and_validate` (строки 68-100) — `summary` меняет тип `str` → `list[str]`
   в модели ответа: добавить проверку `isinstance(parsed.get("summary", []), list)`
   (сейчас поле вообще не валидируется, строка 43-46 не включает его в
   `_LIST_FIELDS`) — добавить `"summary"` в `_LIST_FIELDS` (строки 20-23).
3. `CandidateVacancyAnalysis.summary` (модель, `models/candidate_vacancy_analysis.py`)
   — проверить тип колонки (сейчас, вероятно, `Text`/`str`) — если хранится как
   строка, сменить на `JSON`/список, либо хранить как `"\n"`-джойненную строку и
   парсить на стороне рендера (решить при реализации — что проще не ломает
   существующие консьюмеры этого поля, если такие есть).
4. `PROMPT_VERSION` (строка 13) — бампнуть `"fit-scoring-v2"` → `"fit-scoring-v3"`.
